Platform pod The thing we're building

WorkClone's own platform

WorkClone is not an AI tool vendor. We are a platform company. The platform is what makes clones scalable, secure, auditable, and sellable at enterprise prices — and it raises four questions about how we build and run it.
What "our own platform" means
The infrastructure WorkClone owns, controls, and compounds value on
  • One system of record. Every clone's identity, memory, conversation history, prompt versions, knowledge base, compliance guardrails, and audit trail lives in WorkClone's own data layer — not inside any third-party tool.
  • Multi-tenant by design. Each client's data is fully isolated from every other client. Security, compliance, and auditability are architecture — not add-ons.
  • Providers are replaceable. Voice, workflow, and AI providers sit beneath our platform and can be swapped without WorkClone losing its IP, its client relationships, or its data.
  • Validated in production. The platform has been cleared by an ASX-listed, regulated enterprise client — a standard that is hard to earn and directly blocks competitors.
Why this matters for the Express lane Express clones run on top of this same platform. The control plane is what means a fast Express deployment is still secure, still auditable, and still expandable into a full enterprise engagement — rather than throwaway software.

Session 3 Architecture

The control plane + the isolation question

The control plane is WorkClone's system of record — the layer we own that makes our clones portable, auditable, and proprietary regardless of which third-party tools sit beneath it.
What is the control plane?
Think of it like this
Your phone stores your contacts, messages, and photos — regardless of which app you use to send a message. The control plane is WorkClone's equivalent: the layer that stores everything important about a clone, so that if we swap ElevenLabs for a different voice provider tomorrow, the clone's memory, personality, and history all stay with us — not with the vendor.
What lives in the control plane
  • Clone identity, personality, and voice configuration
  • Full conversation history and memory
  • Prompt versions and knowledge base documents
  • Compliance guardrails and escalation rules
  • Audit trail — every action, every interaction
  • Client data, securely isolated per tenant
The isolation question — major commercial opportunity
Can desktop agents run fully isolated?
Can OpenClaw / Claude computer-use agents operate in a sandboxed environment where client data never touches the open internet? If yes, this is a trust differentiator that most competitors cannot offer.
  • VM-per-client. Each desktop agent runs in a dedicated virtual machine. No shared state between clients.
  • No outbound internet. LLM calls route through WorkClone's own proxy. Nothing leaves to the open web.
  • Full audit trail. Every click, every field entry, every document read — logged before the agent acts.
  • Human in the loop. High-risk actions flagged for approval before execution, not after.
